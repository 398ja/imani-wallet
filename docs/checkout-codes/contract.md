# Checkout codes: the shared contract (#402)

The one place the wallet, the code store (`imani-checkout-codes`), the PHP core
(`imani-coupon-core`) and gateway-customer agree on bytes. Each of them tests
against `vectors.json` next to this file. The issue (#402) gives the reasons, and this
file only fixes the wire format.

## 1. The code

| Property | Value |
| --- | --- |
| Alphabet | Crockford base32: `0123456789ABCDEFGHJKMNPQRSTVWXYZ` (no I, L, O, U) |
| Body | 12 symbols: 11 random data symbols (55 bits) + 1 check symbol |
| Check symbol | Luhn mod 32 over the 11 data symbols (see below) |
| Display form | `IMANI-XXXX-XXXX-XXXX` |
| Compact form | `IMANIXXXXXXXXXXXX` (17 characters). Used where hyphens are not allowed (Shopify gift cards: 8-20 alphanumerics) |
| Generated by | the code store, from a CSPRNG, retrying on a collision |

55 bits rather than 60: the display grouping has 12 body symbols and one of
them is the check. R0 makes a guess worth nothing on PHP platforms, and the
lookup is authenticated and rate limited (R2, R3), so 55 bits is ample.

### Luhn mod 32

`value(c)` is the index of `c` in the alphabet.

```
check(data):                      # data = 11 symbols
  factor = 2, sum = 0
  for c in reversed(data):
    a = factor * value(c)
    sum += a // 32 + a % 32
    factor = 3 - factor           # 2,1,2,1,...
  return alphabet[(32 - sum % 32) % 32]

valid(body):                      # body = 12 symbols, check last
  factor = 1, sum = 0
  for c in reversed(body):
    a = factor * value(c)
    sum += a // 32 + a % 32
    factor = 3 - factor
  return sum % 32 == 0
```

It catches every single-symbol typo and most adjacent swaps, locally, before
any network call.

### Normalising what a person typed

In this order:

1. Uppercase (ASCII only).
2. Delete spaces, tabs, `-`, `_`, `.`.
3. The result must start with `IMANI`. Strip it. (The prefix is matched
   **before** step 4, because `IMANI` contains an `I`.)
4. In the body, map `O`→`0`, `I`→`1`, `L`→`1`. Any other symbol outside the
   alphabet (including `U`) makes the input **not a code**.
5. The body must be exactly 12 symbols and pass `valid`.

The result is the **canonical code**: the compact form, `IMANI` + body.
Anything that fails steps 3-5 is "not an Imani code". Platforms leave it alone
so ordinary coupons keep working. Failing the check symbol alone is a typo,
reported as *"Check the code: a character looks wrong."*

### What the store keeps

The store never keeps the code. It keeps
`code_hash = hex(sha256(utf8(canonical code)))`, and looks up by it. A dump of
the database names no code. Logs show at most `code_hash[0..12]`.

## 2. A part

One coupon locked to the shop key `S`:

```
P2PK_VOUCHER(data = 02‖S, locktime = x, refund = [02‖R], sigflag = SIG_ALL, n_sigs = 1,
             voucher_id, <the coupon's terms>, max_sats)
```

This is exactly `linkLockProposal`'s shape (`src/lib/cashlinkLock.ts`), signed
by the same gateway route (`POST /api/v1/wallet/vouchers/cashlink/lock`), with
`S` in place of the link key. Rules:

- `R ≠ S`. `R` is per part and derived (`imani-checkout-refund/v1/` label),
  never the customer's identity key.
- Every part of one code has the **same** `x`, the same `unit`, and the same
  issuer (the stall).
- `assertNotOpenAfterLocktime` holds for every part.
- A part travels as a `cashuB` token with exactly one proof.

## 3. The code store API

Base path `/v1/checkout-codes`. All calls are NIP-98 (kind 27235, `u` = the
full URL, `method`, and `payload` = sha256 of the body for POSTs). Amounts are
integers in the unit's **minor units**. Times are epoch **seconds**.

### `POST /v1/checkout-codes`: deposit (customer)

```json
{
  "idempotency_key": "uuid",
  "stall_pubkey": "x-only hex",
  "shop_key": "x-only hex (S)",
  "unit": "eur",
  "amount": 2500,
  "expires_at": 1767000000,
  "parts": [ { "token": "cashuB…", "amount": 1000 }, { "token": "cashuB…", "amount": 1500 } ]
}
```

- The NIP-98 caller is the customer. Change and returns are locked to it.
- `amount` must equal the sum of the parts' `amount`, and each part's `amount`
  must equal its credited face value (`creditableFaceValue`).
- 1 ≤ parts ≤ 20.
- Verification is all-or-nothing (R8). One bad part refuses the deposit, with
  `refusal` naming the first problem and `part` its index.

`201 {"code": "IMANI-…", "status": "reserved", "expires_at": …}`. The same
`idempotency_key` from the same caller replays the same answer.

Refusals (`422 {"refusal": NAME, "part": i}`): `MALFORMED`, `TOO_MANY_PARTS`,
`AMOUNT_MISMATCH`, `UNIT_MISMATCH`, `NOT_AUTHENTIC`, `WRONG_ISSUER`,
`WRONG_LOCK_KEY`, `NOT_A_LOCK` (shape), `LOCKTIME_WITHOUT_REFUND`,
`MIXED_EXPIRY`, `EXPIRY_OUT_OF_WINDOW`, `ALREADY_SPENT` (NUT-07),
`DUPLICATE_PART`. `409 MINT_UNAVAILABLE` is retryable.

### `GET /v1/checkout-codes/{code}`: look up (shop)

The NIP-98 caller must be the code's `S`. `{code}` is any typed form. The store
normalises it.

`200`:
```json
{ "status": "reserved|held|redeemed|cancelling|cancelled|expired",
  "amount": 2500, "unit": "eur", "expires_at": 1767000000, "stall_pubkey": "…",
  "held_by": "order ref, only when held by this caller",
  "parts": [ { "amount": 1000, "splittable": false, "min_step": 1 }, … ] }
```

An unknown code, a code for another `S`, and a malformed code all get the
**same** `404 {"refusal":"NOT_FOUND"}`, byte for byte (R2).

### `POST /v1/checkout-codes/{code}/hold`, `/release`, `/redeem` (shop)

Body `{"order_ref": "string ≤ 128"}`.

- `hold`: `reserved → held`, with a TTL (default 30 min, refreshed by a repeat
  hold from the same `order_ref`). Holding again with the same `order_ref` is
  idempotent. A different `order_ref` gets `409 HELD`.
- `release`: `held → reserved`, for the holding `order_ref` only. Otherwise it
  is a no-op `200`.
- `redeem`: `held → redeemed`, for the holding `order_ref` only. Returns
  `{"parts":[{"token":"cashuB…","amount":…}], "customer_pubkey":"…"}`. A replay
  with the same `order_ref` returns the same body (R4).
- On any other state these return `409 {"refusal": "<STATE>"}`.

### `POST /v1/checkout-codes/{code}/cancel` (customer, the depositor only)

`reserved → cancelling`. `409 HELD` while held.

### `POST /v1/checkout-codes/{code}/cancelled` (shop)

Body `{"tokens":["cashuB…"]}`: the parts, swapped back and locked to the customer.
`cancelling → cancelled`, and the tokens go to the outbox for the customer.

### `POST /v1/checkout-codes/{code}/change` (shop, after redeem)

Body `{"tokens":["cashuB…"]}`: change and unneeded parts locked to the
customer. They go to the outbox.

### `GET /v1/checkout-codes/mine` (customer)

The caller's codes, newest first:
`[{ "code", "status", "amount", "unit", "expires_at", "shop_key", "stall_pubkey" }]`.
This is the only place the store returns a code, and only to its depositor. The
store therefore keeps the code **encrypted** for the depositor too: AES-GCM under a
server key, beside `code_hash`.

### State machine

```
reserved ──hold──▶ held ──redeem──▶ redeemed
   │  ▲              │
   │  └──release / TTL┘
   ├──cancel──▶ cancelling ──cancelled──▶ cancelled
   └── now ≥ expires_at (also from cancelling and held) ──▶ expired
```

Every transition is one conditional `UPDATE … WHERE status = ?`, so exactly one
writer wins.

## 4. The stall's profile field

On the stall's kind-30078 `imani:merchant` record (ADR 0012):

```json
"online_shop": { "url": "https://shop.example", "redeem_key": "<S x-only hex>",
                 "platform": "woocommerce|wordpress|magento|shopify", "since": 1767000000 }
```

The wallet takes `S` only from here (R7). It is absent, malformed, or not
64-hex: no online shop.
